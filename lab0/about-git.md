Ветка в Git — это лёгкий указатель на определённый коммит внутри одного и того же репозитория, а не физическая копия всех файлов проекта. Копия папки создаёт дубликат всех данных на диске, занимает место и быстро рассинхронизируется с оригиналом. Ветка же позволяет вести параллельную разработку в одном проекте и безболезненно сливать изменения обратно через git merge.



Если удалить рабочую папку проекта, но сохранить скрытую папку .git, вся история коммитов, ветки и настройки останутся целыми, потому что именно .git хранит все данные репозитория. Рабочие файлы можно восстановить командой git checkout . или git restore ., взяв их из последнего коммита. То есть потеряется только текущее состояние файлов, но не сама история проекта.



Pull Request нужен для того, чтобы изменения сначала прошли проверку командой, а только потом попали в основную ветку main. Коллеги могут оставить комментарии, найти ошибки и предложить правки — это называется code review. Прямые коммиты в main рискованны: один разработчик может случайно сломать рабочий код, и никто это не заметит до релиза.
